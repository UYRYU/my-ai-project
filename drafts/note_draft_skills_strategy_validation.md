## 1. きっかけ：Anthropic 動画で紹介された Agent Skills という仕組み

- 要するに「特定の手順を毎回同じ品質で実行させる仕組み」
- 自動売買 Bot 検証で同じことをずっと手作業でやっていた（戦略書く → backtest → metrics 確認 → 何が原因で負けたか考える）
- 「これを skill 化したら、戦略間の比較が公平になる」と思った
- 1 日で構築 → 戦略 7 本にぶつけてみた、というのが今日の作業

骨子はそれだけ。実装は Claude Code セッション内で 8 割書かせている（手動で書いたのはプロンプトとレビュー）。

## 2. Skill とは何か（30 秒で分かる説明）

Anthropic 公式仕様（[Agent Skills](https://www.anthropic.com/news/skills) に対応するもの）：

- `.claude/skills/<skill-name>/SKILL.md` にフロントマターと手順を書くだけ
- フロントマターに `name` と `description` を書く
- 関連スクリプトを同じディレクトリに置く
- Claude Code は会話文脈に応じて、その skill を呼び出して手順通り実行する

例：今回作った `.claude/skills/backtest/SKILL.md` の冒頭。

```markdown
---
name: backtest
description: 全Bot共通のバックテスト標準手順。新しい戦略は必ずこの手順で検証する。
---
```

要点：
- スラッシュコマンドではない（裏で自動的に呼ばれる）
- 「曖昧な検証を防ぐ」のが主目的
- 戦略コードは別、skill は手順の標準化

## 3. 検証フレームワークの構築：backtest skill / walk-forward skill

`feature/test-backtest-skill-eoRiV` で構築、main にマージ済（commit `3f94b23`）。

### backtest skill
- 入力：戦略ファイル（Python）、シンボル、時間足、期間、資本、手数料、滑り
- 出力：`results/<strategy>_<timestamp>/` に `metrics.json` / `trades.csv` / `equity_curve.png`
- 合格判定（SKILL.md 規定）：
  - 取引数 ≥ 100
  - 勝率 ≥ 40%
  - PF ≥ 1.3
  - 最大 DD ≤ 30%
  - シャープ ≥ 1.0
  - 期待値 > 0

### walk-forward skill
- backtest の上位スキル：IS（最適化）→ OOS（検証）を時間でローリング
- 戦略クラスに `optimize()` と `set_params()` を追加実装する規約
- 出力に `per_window.csv`、`combined_oos`、`stability` 指標
- 過学習判定：mean(IS PF)/mean(OOS PF) > 2.0 / OOS PF < 1.0 が半数以上

両 skill とも、戦略は `Strategy` クラスを実装するだけで使える。動作確認用に `strategies/dummy.py`（150 ランダム取引）で配管テスト → 通過確認。

### この skill を作ったメリット（実際に効いた点）

- 戦略 7 本すべて、同じ手数料（0.1%）、同じ滑り（0.05%）、同じ計算式で metrics 取得
- 「結果が違うのは戦略の違いだけ」と保証される
- 1 戦略あたりの検証工数：戦略コード書く → コマンド 1 行で全部出る
- IS-OOS 劣化率が見えるので「過学習か、エッジ無いか」が区別できる

### 4-1. Dual EMA + ATR Filter（戦略 #1）

`feature/dual-ema-atr-strategy` commit `9d51061`。

仕様：Fast EMA (20) / Slow EMA (50) クロスでエントリー、ATR(14) が直近 50 本平均の 0.8 倍以上の時のみ約定許可、TP=2×ATR / SL=1.5×ATR。

- 取引数 411（十分なサンプル）
- PF 0.63、勝率 39.4%、Sharpe -3.08、MaxDD 80.6%、総リターン -78.6%
- WF: IS PF も 8/8 区間で 1.0 未満 → **「過学習」ではなく「ベース戦略にそもそもエッジがない」**
- IS-OOS 劣化率は 11% と小さい（IS で見つけたシグナルが OOS でも同じパターンで負ける）
- 結論：BTC 1h 環境で EMA クロス + ATR フィルタ単体は手数料負け

### 4-2. Bollinger Band Mean Reversion（戦略 #2）

`feature/mean-reversion-bb` commit `2d9e28c`。

仕様：BB 外側タッチ + RSI 30/70 + EMA(200) フラット〜順方向。TP=SMA(20) タッチ、SL=2×ATR、時間ストップ 24 本。

- 取引数 271、PF 0.43、勝率 42.8%、Sharpe -2.87、総リターン -71.2%
- WF: IS PF 最大 0.88、OOS PF 最大 0.84 → **クラシックな過学習パターン**（IS で 0.88、OOS で 0.56 まで落ちる）
- IS-OOS 劣化率 23.2%
- 強上昇トレンド（2024 Q4 BTC $60k → $95k）で OOS PF=0.00 / 3 trades 全敗 = 強トレンド下のショート逆張りが完全に死ぬ
- 結論：BTC 1h で平均回帰系は強トレンドリスクが大きすぎる

### 4-3. Donchian Breakout + ATR Trailing（戦略 #3）

`feature/breakout-donchian` commit `f1b4d0b`。

仕様：直近 N 本高安ブレイクでエントリー、ATR トレーリング、反対ブレイクで決済（ドテンしない）。

- 取引数 768、PF 0.68、勝率 29.2%（典型的トレンドフォロー値）、Sharpe -2.27、総リターン -92.6%
- WF mean IS PF 0.84、mean OOS PF 0.79、**IS-OOS 劣化率 5.3%（3 戦略中最小）**
- これは「過学習ではない、構造は機能している、ただし負ける」状態
- 取引数 768 が多すぎ → 手数料 0.1% × 滑り 0.05% で 1 トレード往復 0.3% コスト × 768 = 230% を吐き出している計算
- 結論：構造的に何かを拾っているが、コスト構造を超えるほどではない → **次の改良はフィルタを足してコストを減らす方向**

### 4-4. Donchian Breakout + 4h EMA トレンドフィルタ（戦略 #4）

`feature/breakout-htf-filter` commit `f0c367c`。

仕様：戦略 #3 に、上位足 4h の EMA(50) の傾きが順方向のときだけ約定する条件を追加。look-ahead 回避のため `slope.shift(1)` で「進行中の 4h バー」を絶対に参照しない設計。

| 観点 | 素 Breakout | + HTF |
|---|---|---|
| backtest PF | 0.68 | **0.91** |
| backtest 総リターン | -92.6% | **-29.1%** |
| WF 結合 OOS PF | 0.81 | **1.0029** |
| WF 結合 OOS 総リターン | -66.4% | **+0.41%** |
| WF 結合 OOS MaxDD | 73.7% | **24.0%** |

**初の break-even 超え**。フィルタは：
- 取引数を 377 → 154 に削減（だまし breakout 排除）
- 勝率はほぼ変わらず（29% → 24%、むしろ下がる）
- 勝ち負け比 R:R が改善（avg win $297 / avg loss $119 → 2.5x）

ただし WF combined OOS は W1 (Q1 2023 BTC $16k→$28k 回復ラリー、OOS PF 2.72) に依存。W1 を除くと平均 OOS PF ≈ 0.87 まで落ちる。「**強トレンドの quarter で大きく取り、レンジでぶら下がる**」プロファイル。

### 4-5. アセット汎化検証

`feature/breakout-htf-multi-asset` commit `2be647d`。

「BTC 22-24 で動いたのは偶然か」を切り分けるため、実データの取れた範囲で 2 軸検証：

| アセット × 期間 | WF OOS PF | 総リターン | 判定 |
|---|---|---|---|
| BTC 2022-24（凪寄り、これまでのベース）| 1.00 | +0.4% | OVERFIT |
| BTC **2017-19**（高ボラ era）| **1.28** | **+62.5%** | OVERFIT |
| ETH **2017-19**（極端高ボラ）| **1.63** | **+137%** | **PASS** |

注：ETH/SOL/XRP の 2022-2024 実データが取れず、`btc-trend-long-bot` ブランチに ETH/SOL/XRP の 1h CSV があったが価格レベル検証で**合成データと判明**（2024 年末 ETH $11,349、SOL $838 等）。やむを得ず ETH/BTC の 2017-2019 実データで「同戦略・別アセット・別時代」検証。

**仮説の修正**：「BTC 特有の偶然」ではなく「**市場レジーム依存**」が本質と判明。価格レンジ比（高値/安値）と OOS PF に強い正相関：

- BTC 22-24: 6.2x → PF 1.00
- BTC 17-19: 25x → PF 1.28
- ETH 17-19: 178x → PF 1.63

### 4-6. + ATR Regime（常時 ON、戦略 #5）

`feature/breakout-htf-regime` commit `8316b68`。

「凪期で発生するだまし breakout を抑えれば、もっと良くなるはず」という仮説。短期 ATR(14) を直近 200 本平均で割り、1.0 倍以上のときだけエントリー許可。

結果は **見事に「凪向け改良」と判明**：

| 観点 | 戦略 #4 (素) | 戦略 #5 (+Regime) | 変化 |
|---|---|---|---|
| BTC 22-24 PF | 1.00 | **1.11** | +11% |
| BTC 22-24 リターン | +0.4% | +10.1% | +9.7pt |
| BTC 17-19 PF | 1.28 | **0.97** | **-24%** |
| BTC 17-19 リターン | +62.5% | **-3.6%** | **-66pt** |
| ETH 17-19 PF | 1.63 | **1.37** | -16% |
| ETH 17-19 リターン | +137% | **+61.9%** | -75pt |

**凪相場で改善、高ボラ相場で改悪**。原因：高ボラ era では ATR baseline 自身も高くなり、`atr / baseline >= 1.0` 閾値が単に「過去平均並みのボラ」を要求するだけで、有用な breakout 期も拒否してしまう（ETH 2018 Q1 暴落の前半をスキップ等）。

### 4-7. + 長期 ATR メタ判定（Adaptive、戦略 #6）

`feature/breakout-htf-adaptive` commit `9340f66`。

戦略 #5 の知見を踏まえ、「凪 era だけ Regime フィルタ ON、高ボラ era は OFF」と動的切替する**メタフィルタ**を追加。

仕様：
- 長期 ATR 平均（過去 720 本 = 30 日分）/ 現在価格 ≤ 1% なら「凪 era」と判定
- 凪 era → 戦略 #5 として動作
- 高ボラ era → 戦略 #4 として動作
- メタフィルタのパラメータ（720 本 / 1%）は固定、optimize グリッドに含めない（過学習防止）

結果は **3 環境すべてで PASS**：

| アセット | calm-bar % | 戦略 #4 PF | 戦略 #5 PF | **戦略 #6 PF** |
|---|---|---|---|---|
| BTC 22-24（凪）| 87.2% | 1.00 | 1.11 | **1.27** |
| BTC 17-19（高ボラ）| 47.1% | 1.28 | 0.97 | **1.35** |
| ETH 17-19（極端高ボラ）| 20.5% | 1.63 | 1.37 | **1.61** |

特に注目：
- **BTC 22-24 は素戦略の +27%**（メタフィルタが凪相場で更に改善）
- **BTC 17-19 / ETH 17-19 は素戦略の性能をほぼ完全に回復**（高ボラ era では Regime をバイパス）
- IS-OOS 劣化率：BTC 22-24 で -0.98%（ほぼゼロ）、ETH 17-19 で -33%（OOS が IS を上回る）

この時点で「環境適応型戦略の実証成功」と判断した。**ただし注意点として、2020-2021 の真データが未検証であることを Claude Code 側から明示的に指摘されていた**。

### 4-8. 2020-2021 実データ検証：完全崩壊（戦略 #7）

`feature/breakout-htf-adaptive-2020-2021` commit `3ace7a9`。

戦略コード・パラメータは戦略 #6 のままで、データだけ 2020-2021 BTC 実データ（COVID 暴落 → DeFi 夏 → ATH $69k）に差し替えて検証。

データ取得経緯（正直に書く）：
- ccxt 12 取引所、HTTP 直接、CryptoCompare/CoinGecko 等 → **全部 NetworkError か 403**
- 唯一 `*.github.com` だけが到達可能
- 既存ブランチを深堀りで再スキャン → `automated-trading-system-pPAds` 内に `btcusd_15m_2020.csv` と `_2021.csv` を発見（前回までのスキャンで `*_1h.csv` パターン優先しすぎて見落としていた）
- マイルストーン検証：2020-03-12 panic low $4,007、2021-11-10 ATH **$69,000 ぴったり** → 実データ確定

結果（仮説 PF 1.0-1.5 → 実測完全に逆）：

| 観点 | 値 | コメント |
|---|---|---|
| backtest 取引数 | 202 | OK |
| backtest PF | **0.64** | 過去最悪レベル |
| backtest 総リターン | **-69.3%** | |
| WF 結合 OOS PF | **0.46** | |
| WF 結合 OOS 総リターン | **-77.2%** | |
| WF OOS PF < 1.0 区間 | **4/4 (100%)** | |
| IS-OOS 劣化率 | **43.3%** | クラシックな過学習サイン |
| calm-bar 比率 | 50.5% | 仮説どおり混在 era |

サブ期間別の挙動（参考、各取引数 < 100 で正式 PASS 不可）：

| サブ期間 | 取引数 | PF | リターン | 観察 |
|---|---|---|---|---|
| 2020-Q1（COVID）| 17 | 0.66 | -11.9% | 03-12 short +$1,356 で底捕捉、翌 03-13 short -$962 で V 字反発 whipsaw |
| 2020-Q3-Q4（DeFi 夏）| 33 | 1.00 | +0.2% | **唯一 break-even** — 凪フィルタが働いた |
| 2021-Q2（May crash）| 20 | 0.80 | -7.8% | 急変対応失敗 |
| **2021-Q4（ATH）** | **19** | **0.41** | **-14.2%** | 史上最強上昇期に最悪、ATH 後の急反落で long 連敗 |

**何が起きたか（事実ベースの解剖）**：

1. メタフィルタは仕様どおり動作（calm 50.5%、仮説 50-70% の下限に収まる）
2. しかし CALM 取引も HIGH-VOL 取引も両方損失（PF 0.68 / 0.61）
3. **メタフィルタの問題ではなく、ベース戦略（Breakout+HTF）が 2020-2021 era で edge 消失**
4. 1 quarter 単位でレジーム交替する era では、12 ヶ月 IS でフィットしたパラメータが OOS 3 ヶ月で既に古い
5. 特に 2021-Q4 ATH 到達後の急反落で trailing 系が壊滅 → トレンドフォロー戦略の根本的限界

look-ahead 検証：全 202 entry が次バー open と完全一致、COVID 底ショートも intrabar 約定で正当。**バグではなく戦略の真の限界**。

## 5. 何が学べたか

| 戦略 | コンセプト | 最良 PF | 教訓 |
|---|---|---|---|
| #1 EMA Cross | 連続トレンドフォロー | 0.53 | クロス単体は手数料負け |
| #2 BB Mean Rev | 逆張り | 0.58 | 強トレンドで死ぬ |

| #7 (= #6) on 2020-21 | 未見 era 検証 | 0.46 | **崩壊、時代依存判明** |

### 技術的な発見

1. **「IS PF と OOS PF の劣化率」は過学習診断に強い**
   - 戦略 #1 は全 windows で IS PF も 1.0 未満 → エッジ無し
   - 戦略 #2 は IS で良いが OOS で 23% 劣化 → 過学習
   - 戦略 #6 は IS-OOS 劣化率がほぼゼロ → 構造的に安定
2. **walk-forward の機械的 PASS 判定は「内容」を見ない**
   - 戦略 #5 BTC 17-19 は PASS だが結合 OOS PF=0.97 で実質負け
   - PASS だけ見て本番投入しないこと
3. **メタフィルタという改良手法は機能する**
   - ベース戦略のパラメータをいじらず、「いつ使うか」を別レイヤで判定
   - 過学習リスクが低い（メタ層は固定、optimize に含めない設計）
4. **しかし「未見 era」での崩壊リスクは消えない**
   - 戦略 #6 は 3 環境 PASS → 1 環境（2020-21）で総リターン -77%
   - 検証 era を増やしてもサンプル外のリスクは消えない
5. **look-ahead バイアスは検証時に必ず数値で確認する**
   - 各戦略で entry_price が次バー open と完全一致するか、`shift(1)` で過去のみ参照しているか
   - 戦略 #4 の 4h リサンプリングと戦略 #6 の長期 ATR 平均は特に検証コストが大きい

### Skills + Claude Code という開発スタイルについて

- **再現性**：skill のおかげで戦略 7 本すべて同じコストモデル・同じ計算式で評価。比較が公平
- **速度**：1 戦略あたり、プロンプト書く + コード生成 + 検証 + commit で 30-60 分
- **実装は Claude Code が 8 割書いている**：手動で書いたのはプロンプト、メトリクス確認、仕様判断、レビュー
- **失敗が検出可能**：埋もれていた look-ahead や合成データ混入を、検証手順の標準化で発見できた
- **過学習を構造的に避ける設計が可能**：メタフィルタを optimize グリッドに含めない、IS-OOS 劣化率を必ず確認、等

注：Claude Code を持ち上げすぎないため明記しておくと、**正解にたどり着く方向に誘導するプロンプト判断は人間側の責務**。AI に「結果見ながらパラメータ調整しない」「合成データを実データと偽らない」「未見データで検証する」と毎ターン制約を書かないと、過学習方向に最適化される。

## 6. 次の展望

事実として、**今日見つかった戦略 #6 は本番投入できる水準ではない**：
- 2020-2021 のような「急変連発 era」で戦略は崩壊する
- 3 環境 PASS は「比較的トレンドが続く era」に偏ったサンプル

可能な次ステップ（推測、検証はまだ）：
- **第二段メタ層**：「市場が短期で暴れる era」を検出して戦略を完全に OFF にする層を追加（ただし 2020-2021 を後付けで除外する過学習リスクあり）
- **戦略本体の改善**：trailing 一律ではなく、ボラ加速時はタイト利確、低ボラ時は伸ばす等
- **アセット分散**：単一銘柄ではなくバスケット運用で era 依存を希釈
- **本気でやるなら**：別アセット（FX、株式インデックス）の同期間検証で「BTC 2020-21 era だけ崩壊するのか、それとも 2020 系列の市場構造そのものが breakout 系を殺すのか」を切り分け

書いている自分用備忘：
- 戦略を「勝てる/勝てない」で見るのではなく「どの era で機能しどの era で死ぬか」のマップ作りが本質
- 7 戦略の検証で得た本物の成果は「単一戦略への期待を捨てる根拠」と「フレームワーク」の 2 つ
- 次の作業は戦略の追加ではなく、運用判断レイヤ（era 検出と戦略 ON/OFF）の方が筋

## 結論

- ナイーブな単一戦略は BTC 1h スポット手数料 0.1% で勝てない（実証済）
- フィルタを重ねていくと break-even は超えられる（戦略 #4 で実証）
- メタフィルタによる環境適応は機能する（戦略 #6 で実証）
- しかし未見 era で崩壊するリスクは消えない（戦略 #7 で実証）
- **本記事の真の成果は「1 つの完璧な戦略」ではなく「フレームワーク」**：Skills 化したから 1 日で 7 戦略の弱さが定量的に可視化された

「これで稼げる」結論にはしない。事実上、稼げる戦略は今日見つかっていない。だが「自分の戦略アイデアの解像度」は明らかに上がった。これが個人開発でフレームワークを作る価値だと思う。
